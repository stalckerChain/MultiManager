# TASK — Подтверждение удаления сущностей

## Цель

Добавить единое обязательное подтверждение перед удалением профилей, прокси,
расширений и проектов.

Перед фактическим удалением пользователь должен:

1. увидеть всплывающее окно с предупреждением;
2. установить чекбокс «Я понимаю, что удаление необратимо»;
3. нажать кнопку `OK`.

Без установленного чекбокса удаление не выполняется, а кнопка `OK` недоступна.

Подтверждение должно работать для одиночных удалений и существующих массовых
удалений. Массовое удаление расширений добавлять не требуется.

## Подтверждённое текущее поведение

- Одиночное удаление профиля вызывается из меню строки в
  `gui/src/renderer/views/Profiles.vue`.
- Массовое удаление профилей выполняется функцией `bulkDelete()` по
  `selectedRowKeys`.
- Backend запрещает удаление профиля, если его `status` не равен `stopped`.
- Одиночное удаление прокси вызывается кнопкой строки в
  `gui/src/renderer/views/Proxies.vue`.
- Массовое удаление прокси выполняется функцией `bulkDeleteSelected()` по
  `selectedRowKeys`.
- Кнопка `deleteUnused` прокси сейчас вызывает только TODO-функцию и не
  удаляет данные; реализацию удаления неиспользуемых прокси в эту задачу не
  включать.
- Одиночное удаление расширения сейчас защищено `a-popconfirm` в
  `gui/src/renderer/views/Extensions.vue`; его заменить на требуемое модальное
  окно с чекбоксом.
- Массового удаления расширений в интерфейсе нет и добавлять его не нужно.
- Удаление проекта вызывается из `confirmDeleteProject()` в
  `gui/src/renderer/views/Settings.vue` и должно перейти на тот же механизм.
- Backend API и БД уже реализуют DELETE-операции для всех перечисленных
  сущностей; менять API-контракты, схему БД и серверную авторизацию не нужно.
- Все пользовательские строки GUI должны использовать i18n.

## Согласованное решение

### 1. Общий компонент подтверждения

Создать переиспользуемый компонент
`gui/src/renderer/components/ConfirmDeleteModal.vue`.

Компонент должен:

- принимать состояние открытия, заголовок, текст предупреждения и при
  необходимости количество удаляемых объектов через props;
- иметь компактную ширину около `420px` на desktop вместо широкого окна;
- располагать предупреждение и чекбокс вертикально в области содержимого,
  чтобы текст и подтверждение не занимали отдельные боковые колонки;
- при массовом удалении с большим количеством запущенных профилей отображать
  список в пределах окна: содержимое должно помещаться или иметь прокрутку без
  выхода за границы модального окна;
- сохранять стандартный нижний footer модального окна с кнопками отмены и `OK`;
- быть адаптивным: на узком экране использовать доступную ширину с отступами,
  не выходя за границы окна;
- эмитить подтверждение и закрытие/отмену;
- содержать `a-checkbox` с текстом о необратимости удаления;
- сбрасывать состояние чекбокса при каждом новом открытии;
- блокировать `OK`, пока чекбокс не установлен;
- позволять родительскому компоненту передавать состояние загрузки;
- закрываться после отмены или успешного завершения подтверждаемого действия;
- не выполнять API-вызовы самостоятельно.

Не использовать `a-popconfirm` для перечисленных удалений после внедрения
компонента.

### 2. Одиночное удаление

В `Profiles.vue`, `Proxies.vue`, `Extensions.vue` и `Settings.vue`:

- заменить прямой вызов DELETE на открытие общего окна;
- сохранить сущность или идентификатор, ожидающие удаления;
- выполнять DELETE только из обработчика подтверждения;
- показывать состояние загрузки во время запроса;
- сохранять существующие сообщения об успехе и ошибках;
- при отмене очищать ожидающую операцию и не отправлять запрос.

Для расширения подтверждение должно удалять каталог через существующий
`DELETE /api/extensions/:id` только после `OK`.

Для проекта сохранить существующую обработку ошибки конфликта, когда проект
связан с задачами.

### 3. Массовое удаление профилей

Перед открытием окна подтверждения:

- получить выбранные профили из текущего списка по `selectedRowKeys`;
- разделить их на запущенные и доступные для удаления по текущему статусу;
- считать профиль удаляемым только при `status === 'stopped'`.

В окне подтверждения показать пользователю:

- какие профили нельзя удалить, например их имена;
- причину: профиль запущен, его необходимо остановить;
- сколько профилей будет удалено после подтверждения;
- чекбокс необратимого удаления.

После установки чекбокса и нажатия `OK`:

- удалить только остановленные профили;
- не отправлять DELETE-запросы для запущенных профилей;
- обработать ошибки остальных запросов без остановки всей операции;
- после завершения обновить выбор строк и показать результат, включая
  количество удалённых и пропущенных/неудалённых профилей;
- если все выбранные профили запущены, не выполнять DELETE-запросы и сообщить
  пользователю причину.

Одиночное удаление запущенного профиля также не должно отправлять запрос до
подтверждения; после подтверждения backend продолжает быть источником
окончательной проверки состояния.

### 4. Массовое удаление прокси

- Открывать одно окно подтверждения для всего набора `selectedRowKeys`.
- Показывать количество выбранных прокси.
- После `OK` удалять выбранные прокси последовательно или в текущем принятом
  порядке.
- Не менять существующую связь профиля с прокси: backend при удалении прокси
  устанавливает `proxy_id` профиля в `NULL` через `ON DELETE SET NULL`.
- После завершения очищать выбор и обновлять список/сообщение о результате.

## Риски и ограничения

- Массовое удаление профилей должно заранее исключать запущенные профили, а не
  полагаться на последовательные ошибки backend.
- Между предварительной проверкой статуса и подтверждением профиль может быть
  запущен другим действием; backend-проверку нельзя удалять или обходить.
- При массовом удалении часть запросов может завершиться ошибкой. Результат
  должен сообщать фактические успешные и неуспешные операции.
- Удаление проекта может завершиться `409`, если у него есть связанные задачи;
  модальное окно не должно скрывать эту ошибку.
- Удаление расширения физически удаляет его каталог. Предупреждение должно
  явно обозначать необратимость.
- Нельзя выполнять удаление при отмене, закрытии окна или выключенном
  чекбоксе.
- Не включать в область задачи другие удаления, например cookies, проекты из
  других экранов или очистку кэша.

## План реализации

1. Реализовать общий `ConfirmDeleteModal.vue` с props/emits, чекбоксом,
   блокировкой `OK` и сбросом состояния при открытии.
2. Подключить компонент в `Profiles.vue` для одиночного удаления и массового
   удаления с предварительным разделением запущенных и остановленных
   профилей.
3. Подключить компонент в `Proxies.vue` для одиночного и массового удаления.
4. Подключить компонент в `Extensions.vue`, удалив существующий
   `a-popconfirm`; массовое выделение расширений не добавлять.
5. Подключить компонент в `Settings.vue` для удаления проектов.
6. Добавить необходимые ключи во все три файла локализации.
7. Проверить, что отмена, закрытие окна и неподтверждённый чекбокс не вызывают
   DELETE-запросов.

## Проверка

Автоматическая проверка из корня проекта:

```text
npm test
```

Проверка сборки GUI:

```text
cd gui && npm run build
```

Ручная проверка:

1. Открыть удаление одного профиля, прокси, расширения и проекта.
2. Убедиться, что в каждом случае появляется модальное окно с чекбоксом.
3. Проверить, что `OK` недоступна без чекбокса и запрос не отправляется.
4. Установить чекбокс, нажать `OK` и убедиться в успешном удалении.
5. Отменить каждое окно и убедиться, что объект остаётся.
6. Выбрать несколько остановленных профилей и проверить одно общее массовое
   подтверждение и удаление всех выбранных.
7. Выбрать одновременно запущенные и остановленные профили; убедиться, что
   запущенные показаны с причиной и не удаляются, а остановленные удаляются.
8. Выбрать только запущенные профили; убедиться, что DELETE-запросы не
   выполняются и пользователь получает объяснение.
9. Выбрать большое количество запущенных профилей и убедиться, что список
   полностью помещается в окне или прокручивается внутри него без выхода за
   границы модального окна.
10. Проверить массовое удаление прокси и очистку выбора после операции.
11. Проверить ошибку удаления проекта со связанными задачами.
12. Проверить одиночное удаление расширения и отсутствие массового режима для
    расширений.
13. Проверить отображение новых строк на английском, русском и китайском
    языках.

## Критерии готовности

- Перед каждым удалением профиля, прокси, расширения или проекта требуется
  чекбокс и `OK`.
- Массовое подтверждение выполняется одним окном для выбранного набора.
- Запущенные профили не удаляются, явно перечисляются и сопровождаются
  причиной.
- Остановленные профили из того же массового набора удаляются.
- Массовое удаление расширений не добавлено.
- Отмена и неподтверждённое окно не вызывают API DELETE.
- Существующие backend-проверки, API, БД и связи данных не нарушены.
- `npm test` и `cd gui && npm run build` проходят.
