# TASK — Зафиксировать версию 1.4.2

## Цель

Зафиксировать текущую версию приложения MultiManager как `1.4.2` отдельным релизным коммитом и тегом `v1.4.2`.

Это подготовительный шаг. Реализацию новой архитектуры multi-control, native input relay и любые исправления синхронизации вкладок в рамках этой задачи не выполнять.

## План

1. Проверить текущее состояние репозитория командами:
   - `git status --short`
   - `git diff`
   - `git log --oneline -10`
2. Найти все фактические файлы, в которых хранится версия приложения. Не менять версии зависимостей и не выполнять обновление dependency-графа.
3. Изменить версию приложения на `1.4.2` во всех обязательных manifest-файлах проекта и связанных lock-файлах, если они содержат собственное поле версии проекта.
4. Не изменять исходный код, тесты, документацию, зависимости и настройки, не относящиеся к фиксации версии.
5. Запустить минимальную проверку, необходимую для подтверждения корректности изменения версии:
   - `npm test`
   - проверить, что версия во всех изменённых manifest-файлах равна `1.4.2`.
6. Проверить итоговый diff и убедиться, что в коммит не попадут секреты, временные файлы, `node_modules` и чужие несвязанные изменения.
7. Создать коммит с сообщением:

   ```text
   chore(release): set version 1.4.2
   ```

8. Создать аннотированный git-тег:

   ```text
   v1.4.2
   ```

9. После создания проверить:
   - `git status --short`
   - `git log --oneline -1`
   - `git tag --points-at HEAD`

## Ограничения

- Не менять версию выше или ниже `1.4.2`.
- Не запускать `npm run bump`.
- Не выполнять `git reset --hard`, `git checkout --` или другие destructive-команды.
- Не коммитить изменения, не относящиеся к фиксации версии.
- Если в рабочем дереве есть несвязанные изменения, сохранить их и включить в релизный коммит только явно относящиеся к версии файлы.
- Если невозможно однозначно определить полный набор version-файлов или проверка падает, остановиться и сообщить точную причину без создания коммита и тега.

## Результат

Ожидается:

- версия приложения `1.4.2`;
- один релизный коммит `chore(release): set version 1.4.2`;
- аннотированный тег `v1.4.2`, указывающий на этот коммит;
- тест `npm test` завершился успешно;
- после коммита рабочее дерево не содержит изменений, созданных разработчиком.
