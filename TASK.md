# TASK — Нумерация прокси в таблице

## Цель

Добавить на страницу прокси (`Proxies.vue`) колонку `#` с последовательной нумерацией записей в порядке их отображения, аналогично колонке нумерации на странице профилей.

Нумерация должна быть только отображаемым UI-индексом. Она не является идентификатором прокси, не сохраняется в БД и не передаётся в API.

## Подтверждённое текущее поведение

- `gui/src/renderer/views/Profiles.vue:188-196` содержит колонку `#`, использующую поле `profile.number`.
- Профили приходят из API уже отсортированными по `number`.
- `gui/src/renderer/views/Proxies.vue:20-23` отображает `proxiesStore.proxies` с пагинацией.
- Прокси не имеют отдельного порядкового поля для UI.
- `src/db/queries.js:180` возвращает прокси в порядке `created_at`.
- API `/api/proxies` возвращает список целиком; серверную пагинацию и API-контракт менять не требуется.
- Ant Design Vue 4.2.6 передаёт в слот `bodyCell` локальный индекс строки `index`.

## Согласованное решение

### 1. Добавить колонку

В `gui/src/renderer/views/Proxies.vue` добавить первой колонкой таблицы:

```js
{ title: '#', key: 'number', width: 60 }
```

### 2. Выводить номер строки

Расширить параметры слота таблицы с `{ column, record }` до `{ column, record, index }` и обработать `column.key === 'number'` в `bodyCell`.

Номер вычислять на основе страницы и локального индекса строки:

```text
(current - 1) * pageSize + index + 1
```

Требования к поведению:

- первая строка первой страницы имеет номер `1`;
- на второй странице нумерация продолжается, а не начинается заново;
- при изменении размера страницы формула использует новый `pageSize`;
- при добавлении, импорте или удалении прокси номера пересчитываются автоматически;
- значение `record.id` не использовать как номер.

Не изменять `data-source`, store, API, БД, порядок загрузки прокси и CRUD-операции.

## Затрагиваемые файлы

Обязательно:

```text
gui/src/renderer/views/Proxies.vue
```

Тесты и документацию менять не требуется: API-контракт, схема БД и бизнес-логика не меняются. Не добавлять новые зависимости и не изменять версию проекта.

## Риски и ограничения

- Индекс слота должен соответствовать позиции строки внутри текущей страницы; нельзя считать номер только как `index + 1`, иначе на второй и последующих страницах появятся дубликаты.
- Нумерация зависит от текущего порядка `proxiesStore.proxies`, который задаётся backend-порядком `created_at`. Не вводить отдельную сортировку на frontend.
- При смене page size существующий `handleTableChange` должен продолжать корректно обновлять `current` и `pageSize`; не менять его поведение без необходимости.
- Нумерация не должна влиять на `row-key`, выбор строк, действия, редактирование, проверку и удаление.
- Не менять нумерацию профилей.

## Реализация

1. В `Proxies.vue` добавить колонку `#` в начало массива `columns`.
2. Передать `index` из параметров `bodyCell`.
3. Добавить шаблон отображения вычисленного номера для новой колонки.
4. Проверить, что остальные ветки `bodyCell` и существующие обработчики не затронуты.

## Проверка

Автоматическая проверка из корня проекта:

```text
npm test
```

Проверка сборки GUI:

```text
cd gui && npm run build
```

Ручная проверка:

1. Открыть страницу прокси и убедиться, что колонка `#` отображается первой.
2. Проверить последовательность `1, 2, 3...` на первой странице.
3. Перейти на вторую страницу и убедиться, что нумерация продолжается с учётом `pageSize`.
4. Переключить размеры страницы `10`, `20`, `50`, `100` и проверить отсутствие сброса нумерации к `1` на последующих страницах.
5. Добавить, импортировать и удалить прокси; убедиться, что номера пересчитались.
6. Проверить, что выбор строк, кнопки `Check`, `Edit`, `Delete` и связанные профили работают без изменений.
7. Убедиться, что колонка нумерации профилей и их поведение не изменились.

## Критерии готовности

- На странице прокси есть колонка `#`.
- Номера начинаются с `1` и соответствуют порядку отображения.
- Нумерация корректно продолжается между страницами.
- После изменений списка номера пересчитываются.
- API, БД, store и модель прокси не изменены.
- `npm test` и `cd gui && npm run build` проходят.
