# TASK — Рабочий размер страницы профилей и прокси

## Цель

Исправить выбор количества элементов на странице в таблицах профилей и прокси. Сейчас пользователь может выбрать `10`, `20`, `50` или `100`, но таблица продолжает показывать `20` элементов, потому что компонент получает фиксированное значение `pageSize: 20`.

Выбранный размер страницы должен сохраняться между запусками приложения отдельно для профилей и прокси.

## Подтверждённое текущее поведение

Обе таблицы используют одинаковую конфигурацию:

```text
gui/src/renderer/views/Profiles.vue:56-58
gui/src/renderer/views/Proxies.vue:20-23
```

```js
:pagination="{ pageSize: 20, showSizeChanger: true }"
```

Из-за фиксированного `pageSize` выбранное внутреннее состояние пагинации возвращается к `20` при обновлении компонента.

Данные для обеих таблиц загружаются целиком:

```text
gui/src/renderer/stores/profiles.js:10-21
gui/src/renderer/stores/proxies.js:9-19
```

Backend-эндпоинты `/api/profiles` и `/api/proxies` не принимают параметры пагинации и изменяться не должны.

В проекте нет существующего общего механизма сохранения page size. Renderer Electron поддерживает `localStorage`, поэтому для локальной настройки интерфейса не требуется изменение Pinia store, backend или БД.

## Согласованное решение

### 1. Реактивная пагинация

В `Profiles.vue` и `Proxies.vue` заменить inline-конфигурацию пагинации на реактивное состояние компонента.

Для каждой таблицы хранить как минимум:

- `current` — текущая страница;
- `pageSize` — выбранное число элементов;
- `showSizeChanger: true`;
- `pageSizeOptions: ['10', '20', '50', '100']`.

Подключить обработчик изменения таблицы через существующий механизм событий Ant Design Vue. При изменении `pageSize` обновлять реактивное состояние, чтобы выбранное значение не перезаписывалось фиксированным `20`, и всегда сбрасывать `current` на `1`, чтобы пользователь не оказался на несуществующей странице.

### 2. Общая utility-функция

Чтобы не дублировать чтение, запись и валидацию в двух представлениях, создать простую utility-функцию (не composable, не класс и не новый store):

```text
gui/src/renderer/utils/page-size.js
```

Функция должна принимать ключ `localStorage`, допустимые значения и fallback, а также предоставлять операции чтения и записи размера страницы. Внутри utility-функции:

- валидировать значение только против `10`, `20`, `50`, `100`;
- оборачивать каждый вызов `localStorage.getItem` и `localStorage.setItem` в `try/catch`;
- при отсутствии, повреждении, неподдерживаемом значении или исключении `localStorage` при чтении возвращать fallback `50`;
- ошибка записи не должна ломать таблицу или изменение локального состояния.

### 3. Сохранение между запусками

Использовать отдельные ключи `localStorage`:

```text
multimanager.profiles.pageSize
multimanager.proxies.pageSize
```

При инициализации каждой страницы использовать utility-функцию и соответствующий ключ.

После выбора нового размера немедленно записывать его в соответствующий ключ.

При изменении `pageSize` всегда сбрасывать `current` на `1`.

Хранить размер страницы профилей и прокси независимо: изменение настройки на одной странице не должно менять настройку на другой.

## Затрагиваемые файлы

### Обязательно

```text
gui/src/renderer/views/Profiles.vue
gui/src/renderer/views/Proxies.vue
gui/src/renderer/utils/page-size.js
```

Изменить только локальное состояние/configuration пагинации, обработку выбора размера страницы и подключение общей utility-функции. Не менять загрузку данных, CRUD-операции и API-вызовы.

### Тесты

Проверить существующую структуру тестов. В проекте есть unit-тест store прокси (`tests/unit/gui-proxies-store.test.js`), но нет обнаруженных unit-тестов Vue-компонентов для `Profiles.vue` или `Proxies.vue`.

Если тестовая инфраструктура не позволяет быстро монтировать Vue-компоненты, не создавать крупную новую инфраструктуру. Выполнить сборку GUI и провести ручную проверку. При наличии подходящей настройки тестов добавить минимальные проверки:

- выбор `10`, `20`, `50`, `100` меняет размер страницы;
- значение сохраняется под правильным ключом;
- отдельная страница использует свой ключ;
- отсутствующее, повреждённое или неподдерживаемое значение заменяется на `50`;
- исключение `localStorage` при чтении или записи не ломает таблицу.

## Ограничения и риски

- Не менять `src/api/profiles.js`, `src/api/proxies.js`, stores, API-контракт или БД.
- Не добавлять новую зависимость.
- Не изменять версию проекта.
- Не использовать общий ключ для двух таблиц.
- Не принимать произвольные значения из `localStorage`; это пользовательское хранилище может содержать повреждённые данные.
- Не сохранять номер текущей страницы, если это не требуется для корректной работы: после запуска достаточно восстановить размер страницы.
- Каждый вызов `localStorage.getItem` и `localStorage.setItem` должен выполняться внутри `try/catch`. При ошибке чтения использовать `50`; ошибка записи не должна ломать отображение таблицы или выбор размера.
- При любом изменении `pageSize` сбрасывать `current` на `1`.
- Не менять существующее поведение поиска, выбора строк, сортировки и загрузки данных.

## Проверка

### Автоматическая

Из корня MultiManager выполнить:

```text
npm test
```

Из каталога GUI выполнить:

```text
cd gui && npm run build
```

Если будет добавлен отдельный тест для GUI, выполнить соответствующую команду Vitest и указать её результат.

### Ручная

1. Запустить приложение и открыть главную страницу профилей.
2. Проверить, что доступны размеры `10`, `20`, `50`, `100`.
3. Выбрать каждый размер и убедиться, что число отображаемых профилей меняется соответственно.
4. Перезапустить приложение, открыть профили и убедиться, что последний выбранный размер восстановлен.
5. Открыть страницу прокси, выбрать размер, отличный от размера профилей, и убедиться, что настройки независимы.
6. Перезапустить приложение и проверить восстановление размера прокси.
7. Через DevTools установить для каждого ключа значения `''`, `abc`, `0` и `999`; перезагрузить соответствующую страницу и убедиться, что используется `50`.
8. Проверить отсутствие ключей или пустое хранилище: обе таблицы должны использовать `50`.
9. Проверить поиск профилей и работу выбора строк после изменения page size.
10. Проверить, что операции добавления, удаления, проверки и редактирования профилей и прокси не регрессировали.

## Критерии готовности

- В таблице профилей выбор `10`, `20`, `50`, `100` реально меняет количество строк на странице.
- В таблице прокси выбор `10`, `20`, `50`, `100` реально меняет количество строк на странице.
- Выбранный размер профилей сохраняется между запусками.
- Выбранный размер прокси сохраняется между запусками.
- Настройки профилей и прокси хранятся независимо.
- При отсутствующем, повреждённом или неподдерживаемом значении используется `50`.
- Backend, API, БД и stores не изменены.
- Существующие тесты и сборка GUI проходят.
