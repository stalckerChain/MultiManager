# TASK — Отображение соединения прокси в формате host:port

## Цель

В GUI отображение прокси во всех таблицах должно соответствовать канонической конвенции проекта
`host:port` — IP-адрес (host) и порт выводятся одной строкой, а не в две строки, и порт не
скрывается при наличии локации.

## Проблема (факты)

1. `gui/src/renderer/views/Profiles.vue:69-75` (главная, колонка `proxy`):
   - 1-я строка — `host`;
   - 2-я строка — `location || port` → порт виден только при отсутствии `location`;
   - получается «IP в строке 1, порт в строке 2», при наличии локации порт вообще пропадает.
2. `gui/src/renderer/views/Proxies.vue:32-37` (колонка `Connection`):
   - 1-я строка — `host`;
   - 2-я строка — `port`.
3. Канонический формат во всём коде и документации — `host:port` одной строкой:
   - `src/api/browser.js:368` — `--proxy-server` = `type://user:pass@host:port`;
   - импорт прокси `IP:Port:User:Pass` (`gui/src/renderer/views/Proxies.vue:89`);
   - дубликаты по комбинации `host:port` (`src/api/proxies.js:35`, `src/db/queries.js:184`).
4. `gui/src/renderer/views/ProfileModal.vue:74` (выпадающий список выбора прокси) показывает
   `type://host` без порта — вне скоупа данной задачи, не трогать.

## Согласованное решение (гейт №1, подтверждено пользователем)

Формат: **`host:port` одной строкой, вторая строка — локация (если есть)**.

1. `gui/src/renderer/views/Profiles.vue` — колонка `proxy` (блок `column.key === 'proxy'`):
   - 1-я строка: `{{ proxy.host }}:{{ proxy.port }}` (класс `text-xs font-mono`);
   - 2-я строка: `{{ proxy.location }}` (класс `text-xs text-slate-500`) только при наличии
     `location`; если локации нет — вторая строка не выводится.
   - Логика `location || port` удаляется: порт показывается всегда, вместе с host.
2. `gui/src/renderer/views/Proxies.vue` — колонка `Connection` (блок `column.key === 'connection'`):
   - Одна строка: `{{ record.host }}:{{ record.port }}` (класс `text-xs font-mono`);
   - вторая строка с `record.port` удаляется;
   - `Location` уже имеет отдельную колонку — вторую строку не добавлять.

## Реализация

### Шаги

1. Открыть `gui/src/renderer/views/Profiles.vue`, в шаблоне колонки `proxy` (строки 69–75):
   - заменить содержимое строк 71–72:
     - `<div class="text-xs font-mono">{{ proxy.host }}:{{ proxy.port }}</div>`;
     - `<div v-if="proxy.location" class="text-xs text-slate-500">{{ proxy.location }}</div>`;
   - использовать локальную переменную `proxy` (текущий вызов `getProxyById(record.proxy_id)`
     повторяется — при желании сохранить повторение, чтобы не менять структуру; минимальное
     изменение допускается, но не обязательно вводить вычисляемое свойство).
2. Открыть `gui/src/renderer/views/Proxies.vue`, в шаблоне колонки `Connection` (строки 32–37):
   - заменить содержимое на одну строку:
     `<div class="text-xs font-mono">{{ record.host }}:{{ record.port }}</div>`.
3. Логика, данные, API, БД, стили Tailwind — не изменять. Только шаблоны `.vue`.
4. Проверка параметров колонок (ширина):
   - `Profiles.vue:170` — `width: 150` — проверить, что `host:port` умещается в одну строку;
     при частом переносе можно расширить до ~180px (опционально, по визуальной проверке);
   - `Proxies.vue:154` — `width: 200` — достаточно.

### Затрагиваемые файлы

- `gui/src/renderer/views/Profiles.vue` — шаблон колонки `proxy` (строки 69–75);
- `gui/src/renderer/views/Proxies.vue` — шаблон колонки `connection` (строки 32–37).

Больше ничего не менять.

## Что не делать

- Не менять `src/` (бэкенд), схему БД, API-контракты.
- Не менять `ProfileModal.vue` (строка 74 — выбор прокси в модалке профиля) — вне скоупа.
- Не менять колонку Ping / `last_ip`, колонку Location.
- Не добавлять зависимости, не менять версию, changelog, release.
- Не переводить строки (колонки не и18н-зависимы в данных host/port).

## Требования к результату

1. На главной странице (профили) в колонке «Прокси» у каждой записи IP и порт на одной строке
   (формат `host:port`, моноширинный шрифт); локация — второй строкой, если задана.
2. На странице прокси в колонке «Connection» IP и порт на одной строке (`host:port`).
3. Порт больше не скрывается ни при каких условиях (при отсутствии локации отображается `host:port`).
4. Визуально строки не переносятся при ширине колонок по умолчанию (при необходимости ширины
   колонок подстроены).

## Проверка

Компонентных тестов для `.vue` в проекте нет (нет Vue Test Utils), поэтому проверка:

### Автоматическая

```text
cd gui
npm run build   (часть vite build — скомпилирует шаблоны; наличие ошибок сборки)
```

и базовый прогон unit-тестов, чтобы гарантировать отсутствие регрессий в окружении:

```text
npm test
```

### Ручная

1. Запустить GUI (dev или packaged).
2. Главная (`/profiles`): в колонке «Прокси» убедиться, что IP и порт на одной строке через `:`,
   локация — второй мягкой строкой, порт виден и при наличии локации, и без неё.
3. Страница прокси (`/proxies`): в колонке «Connection» IP и порт на одной строке.
4. Проверить отсутствие горизонтальных переносов в колонках на стандартных ширинах.
5. (Опционально) клик по колонке прокси по-прежнему открывает `ProxyModal` — поведение не ломать.

## Риски и ограничения

- Изменение чисто презентационное; риски минимальны.
- Шаблоны `.vue` не покрыты тестами — корректность подтверждается сборкой и ручной проверкой.
- Длинные host (доменные имена > ~20 символов) в колонке 150px на главной могут переноситься —
  решается расширением ширины колонки (опция в шаге 4).

## Критерии готовности

- В обоих файлах `host` и `port` выводятся одной строкой в формате `host:port`.
- На главной локация выводится второй строкой и не заменяет порт.
- Ничего кроме шаблонов двух `.vue` не изменено.
- Сборка GUI проходит; unit-тесты проходят.
- Ручная проверка (экраны главной и прокси) подтверждает формат.
